`@riblt/orp` is the package layer for the Operation Reconciliation Protocol. It provides a transport-neutral TypeScript surface for ORP message types, validation helpers, reusable `riblt` frame exchange helpers, and a session API that orchestrates inventory, chunk, snapshot, and operation repair flows on top of `riblt`.

## Installation

```sh
pnpm add @riblt/orp
```

## Why It Exists

ORP is meant for applications where:

- documents are synced independently
- operation payloads are treated as opaque blobs by the sync layer
- anti-entropy matters more than stream replication
- you want exact repair without Merkle trees or checkpoint feeds
- you may want an optional chunk layer between document inventory and single-op repair

The package gives you the wire model, runtime guards, and reusable orchestration primitives. It does not impose a transport or a specific CRDT.

## Session Example

```ts
import {
  OrpSession,
  type OrpParameters,
  type OrpPeerAdapter,
} from "@riblt/orp";

const params: OrpParameters = {
  symbolSize: 64,
  batchSize: 4,
  hashSeed: "0000000000000007",
};

declare const initiator: OrpPeerAdapter;
declare const responder: OrpPeerAdapter;

const session = new OrpSession(initiator, responder, {
  sessionId: "session-1",
  scopeId: "tenant-42",
  inventoryParams: params,
  operationParams: params,
  chunkTransferThreshold: 4,
  snapshotTailCountThreshold: 12,
});

const result = session.run();
console.log(result.differingDocs);
console.log(result.documents);
```

The adapter methods keep storage and transport outside the package. `OrpSession` only needs inventory, document views, snapshot access, and blob/chunk application hooks.

## Low-Level Example

If you only want the ORP `riblt` frame helpers, the lower-level surface still exists:

## Main Concepts

### `DocSummary`

Each document is summarized with:

```ts
type DocSummary = {
  docHandle: string;
  basisSnapshotId?: string;
  tailCount: number;
  xorA: string;
  xorB: string;
  sumA: string;
  sumB: string;
};
```

The digest fields summarize the operation set after the optional basis snapshot. ORP uses that summary to decide whether a document is the same or different before any per-document repair starts.

### `ChunkSummary`

ORP also supports deterministic unordered-op chunking:

```ts
type ChunkSummary = {
  chunkId: string;
  opCount: number;
  xorA: string;
  xorB: string;
  sumA: string;
  sumB: string;
};
```

The default documented strategy is `hash-bucket/v1`, where each `opId` is assigned to a stable hash bucket. This gives ORP a middle layer between:

- document inventory
- single-operation reconciliation

### Parameters

An ORP session carries two `riblt` parameter sets:

- `inventoryParams`: used for document summary reconciliation
- `operationParams`: used for per-document operation reconciliation

### `OrpSession`

The session layer owns the protocol phases:

- `orp/hello`
- inventory reconciliation
- per-document open and status exchange
- optional chunk reconciliation
- optional snapshot fast path
- operation id repair and blob transfer

`OrpSession#getState()` exposes coarse session progress so a caller can surface current phase and completed documents without inspecting internal transcript details.

### Transcripts

The package ships with `ORP_EXAMPLE_TRANSCRIPTS`, which show:

- inventory reconciliation over document summaries
- chunk reconciliation over deterministic buckets
- snapshot transfer for large divergence
- per-document repair over operation ids
- blob or chunk transfer for missing data

## Message Surface

The package exports TypeScript interfaces for:

- `orp/hello`
- `orp/inventory-frame`
- `orp/inventory-done`
- `orp/doc-open`
- `orp/doc-status`
- `orp/chunk-frame`
- `orp/chunk-done`
- `orp/chunk-get`
- `orp/chunk-put`
- `orp/doc-frame`
- `orp/doc-done`
- `orp/blob-get`
- `orp/blob-put`
- `orp/snapshot-get`
- `orp/snapshot-put`

Each message includes:

- `version`
- `sessionId`
- message-specific fields

The `frame` fields use object-format `riblt` messages so they are JSON-friendly by default.

## Runtime Helpers

For ORP transports that want the workspace object-frame format directly, the package also exports:

## Runtime Validation

The package exports:

- `validateOrpMessage()`
- `validateDocSummary()`
- `validateOrpTranscript()`
- `assertValidOrpMessage()`
- `assertValidDocSummary()`
- `assertValidOrpTranscript()`

Validation checks cover:

- protocol version
- required message fields
- `hashSeed` formatting
- digest and base64 payload formatting
- document summary shape
- chunk summary shape
- `riblt` frame shape
- message array limits

## Production Guidance

### Binary vs Object Frames

Use object frames when:

- your transport is JSON-first
- you want transcript logging and debugging without a binary side channel

Use binary frames when:

- you control both peers
- frame overhead matters more than inspectability
- you are bridging to another runtime using the committed interop fixtures

### Chunk Repair vs Op Repair

The default session logic uses chunk transfer when the estimated operations behind the differing chunks are at least `chunkTransferThreshold`.

Use a lower threshold when:

- op payloads are large
- many operations tend to share the same deterministic buckets

Use a higher threshold when:

- chunk blobs are expensive to materialize
- most diffs are only one or two operations

### Snapshot Fast Path

The session prefers `snapshot-get` / `snapshot-put` when a peer advertises a recent snapshot and its tail is already large enough to justify skipping direct per-op repair.

Use snapshots when:

- documents can diverge by many operations
- replaying all missing op blobs is much more expensive than transferring one basis image plus a tail

Avoid snapshots when:

- snapshots are expensive to compute or store
- most repairs are already small and cheap

### Current Limits

- ORP message arrays are capped at `65536` items
- `riblt` object frames are validated against the same coded-symbol cap
- `riblt` symbol size is capped at `4096` bytes in this implementation

## Demo

The workspace includes `examples/orp-demo`, which demonstrates:

1. inventory reconciliation over document summaries
2. deterministic chunk reconciliation over unordered op sets
3. snapshot transfer for large divergence
4. per-document operation reconciliation when chunk transfer is not worth it
5. chunk or blob transfer, depending on the diff size

It uses a simple grow-only set CRDT, deterministic hash buckets, and synthetic snapshots so each protocol branch stays small and readable.
